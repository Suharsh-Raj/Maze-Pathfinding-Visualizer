UNDERSTAND THE ALGORITHMS

What is the search optimizing?

01 / QUEUE

Breadth-first search

Visits cells in layers using a FIFO queue. Guarantees the fewest moves. Ignores weights while searching, so it may choose an expensive route.

O(V + E)
02 / STACK

Depth-first search

Follows one branch deeply using a LIFO stack, then tries alternatives. Finds a valid route if one exists; neither the fewest moves nor the lowest cost is guaranteed.

O(V + E)
03 / MIN-HEAP

Dijkstra’s algorithm

Expands the cell with the lowest known cost. A binary min-heap selects the next cell. Guarantees minimum total cost for nonnegative movement costs.

O((V + E) log V)
04 / HEURISTIC + MIN-HEAP

A* search

Prioritizes cost so far plus Manhattan distance to the goal × minimum cell cost (1). This heuristic is admissible and consistent here, so A* guarantees minimum cost and settles each cell at most once.

O((V + E) log V)

V is the number of traversable cells; E is the number of connections between neighboring cells. A four-neighbor grid has E = O(V). These are graph-search bounds; this implementation also initializes arrays for all grid cells, including walls. The heap algorithms use lazy duplicate entries; on this grid their worst-case bound is O((V + E) log V). On an equal-cost grid, BFS and Dijkstra have the same optimal path cost, although exploration and tie-breaking can differ. Normal cells cost 1, weighted cells cost 5, and the starting cell costs 0. Neighbor order is always up, right, down, left.
